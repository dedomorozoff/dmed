## 1. P0 — блокирующее (правим сразу)

### 1.1 Data race в `internal/agent`: `Task` читается без блокировки
`Queue` защищает мутации `Task` мьютексом, но `Find` и `Snapshot`
(`internal/agent/queue.go:90`, `:103`) возвращают **те же указатели**.
Пока `Runner` пишет `t.Status` / `t.Changes` / `t.Error` под мьютексом,
TUI в `agentPanel` (`internal/editor/agent_panel.go:316`), `loadAgentChange`,
`handleAgentReview`, `acceptAgentReview` читает эти поля без него.

Это не только «гонка в тесте» — это гонка в проде: задача в состоянии
`running`/`review` перечитывается рендером на каждом кадре, и статусы
`queued → running → review` прыгают ровно в этот момент.

Доказательство (`go test -race ./internal/agent`):
```
WARNING: DATA RACE
Write at 0x... by goroutine 33:
  agent.(*Queue).SetChanges()  queue.go:161
  agent.(*Runner).finish()     runner.go:206
Previous read at 0x... by goroutine 32:
  agent.waitStatus()           runner_test.go:210
--- FAIL: TestRunnerProducesChanges / TestRunnerErrorMarksFailed
```

**Исправление (инвариант, а не заплатка):** очередь отдаёт только копии.
- `Task.Clone()` — копия значения (все поля, `Changes` — новый слайс).
- `Snapshot()` возвращает `[]Task` (значения) вместо `[]*Task`.
- `Find(id) (Task, bool)` вместо `*Task`; пустой `Task.ID` — «не найдено».
- Правки TUI: `agent_panel.go:255, 263, 277, 297`, `mouse.go:349, 732`.
- Тесты: `internal/editor/agent_test.go:33, 132, 159, 195, 210, 254`,
  `internal/agent/queue_test.go:146`.
- `runner_test.go`: `waitStatus` станет безопасным сам по себе.
- Критерий приёмки: `go test -race ./...` зелёный, и в CI добавлен
  отдельный шаг `-race` для `internal/agent` и `internal/editor`.

`-race` ловит класс багов, которых `go vet` не видит (пункт 1.1 — ровно

### 1.4 Починить локальный toolchain
`D:\go\bin\go.exe` — это шим Go 1.25, который сам скачивает 1.26 в
`D:\GoModCache\...\toolchain@v0.0.1-go1.26.0`. Из-за этого `go test -cover`
(и любые команды, пересобирающие std с инструментированием) падают с
`compile: version "go1.26.0" does not match go tool version "go1.25.0"`.
Прогон `vet`/`test` выживает только на уже собранном кеше.
- Вариант А (рекомендую): поставить настоящий Go 1.26 в `D:\go`
  целиком, чтобы `go version` совпадал с `go.mod`.
- Зафиксировать в AGENTS.md подробности этого грабля.

## 2. P1 — надёжность и безопасность

### 2.1 `internal/editor` — god-файл
`editor.go` — 2906 строк, `view.go` — 2341. Один `handleKey` — 565 строк,
один `Update` — 353, в `Model` ~855 полей. Правило проекта («модели —
значения, мутации через небольшие именованные методы») внутри этого файла
уже не выдерживается.
- Вынести `editor.go` по существующим границам AGENTS.md: `keys.go`
  (диспетчер + биндинги в map[string]func), `tabs.go` (open/close/switch),
  `prompt.go` (все `start*Prompt`), `search.go` (find/replace/goto).
- `handleKey` → таблица биндингов `map[string]keyHandler` + fallback
  (перевод `KeyPressMsg` в строку уже есть: `gitKeyName`, `normalizeKey`).
  Это уберёт ~400 строк `switch` и даст места для тестов на таблицу.

### 2.2 `syntax.defaultHighlighter` — глобальное мутабельное состояние
`syntax.go:25,32` — пакетная переменная, пишется из `SetDefault` (вызывается
из `Update` при hot-reload конфига, `editor.go:1255`) и читается из
`syntax.Default()` в горутиках рендера. Формально это гонка и нарушение
«no global mutable state» из AGENTS.md. Данные сейчас не портятся, потому
что `SetDefault` вызывается только из Update-цикла, но мина заложена.
- Вариант: `Highlighter` хранить в `Model` (`m.syn`) и передавать в
  рендер; `SetDefault` убрать, оставив только конструктор.

### 2.3 Агентские инструменты: `allow_run` по умолчанию `always`
`config.go:156` — дефолт `AllowRun: "always"`, `RestrictToRoot: false`.
То есть из коробки модель может (а) выполнить произвольную shell-команду и
(б) читать/писать файлы за пределами проекта. Для позиционирования
«human approves every change» это самый заметный разрыв: изменения
проходят ревью, а побочные эффекты (`RUN`, запись в `~/.ssh/config`) — нет.
- Дефолт `allow_run = ask` (механика уже есть и покрыта тестами),
  в wizard — явный пункт «выполнять команды без подтверждения».
- `restrict_to_root` → `true` по умолчанию; escape hatch через конфиг.
- Индикатор в UI, когда RUN ждёт подтверждения (сейчас состояние
  видно только по тексту в поле ввода).
- Тест на дефолты в `config_test.go`.

### 2.4 Таймауты и отмена у провайдеров
`internal/ai/{ollama,openai}.go` — `ChatStream` без своего `http.Client`
таймаута (таймаут есть только у синхронных `Models`). Долгий стрим с
мёртвым сервером держит горутину и `m.chatBusy` навсегда.
- Общий `http.Client` с `Timeout` для не-стримовых запросов и
  `ResponseHeaderTimeout` для стримов (тело не должно обрываться).
- Проверка `ctx.Err()` в цикле чтения SSE/NDJSON — сейчас есть только в
  тесте отмены (`ai_test.go:100`), в проде отмена чата полагается на
  периферию.

### 2.5 Мёртвый `_ = ` и потеря ошибок в горячих путях
~100 мест `_ = ...`. Критичные для пользователя:
- `editor.go:762, 1127, 2182` — `watcher.Watch/Close` без проверки →
  «файл не под наблюдением» всплывает как «не работает fsnotify».
- `editor.go:1456` — запись в терминал без ошибки.
- `ai_fix.go:283-290` / `ai_inline.go:296` — применение AI-предложения
  пересобирает буфер через select+insert; нет теста на «буфер не меняется,
  если предложение пустое».
- `agent/apply.go:139-145` — откат проглатывает ошибки; это осознанно
  (best-effort rollback), но стоит хотя бы логировать.

### 2.6 `CapturePanicReport` не спасёт от `os.Exit`
`main.go:29,39` — единственные `os.Exit`. Для TUI это значит, что паника
в Update-цикле (вне горутины) уронит редактор.
- Recover в `main` с печатью стектрейса, и `Update` завершать
  перерисовкой статуса вместо падения.

## 4. P3 — продукт (по возрастанию риска)

1. **Undo через `agent.Applier`.** Сейчас принятые агентские изменения
   необратимы: один `git commit` без возможности отката из редактора.
   Минимально: `Ctrl+Z` после принятого агентского diff предлагает
   `git revert` этого коммита (через `internal/vcs`, не через шелл).
2. **`restrict_to_root` на уровне Applier.** Правило проекта говорит
   «агент не пишет мимо ревью», но `Applier` не проверяет, что путь внутри
   проекта. Один вызов — и гарантия становится настоящей.
3. **Контекст для агента.** `SnapshotFiles` (tools.go:395) обходит весь
   проект на каждый вызов инструмента. На больших репозиториях это
   заметная стоимость; нужен кеш снапшота с инвалидацией по mtime/git.
4. **Клавиатурная навигация по help/панелям.** `F1` скроллится, но
   переходы «следующий hunk в панели git», «следующая задача агента»
   завязаны на дублирующиеся `gitKeyName`/`normalizeKey` — пора в одну
   таблицу.
5. **M8 (если нужен следующий рубеж):** реальные LSP capabilities
   (codeAction / formatting) — сейчас только diagnostics + definition,
   и самописный `internal/lsp` в этом слабое место.
